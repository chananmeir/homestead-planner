# Bulk Harvest from Bed-View Pill — Fix Report

**Date**: 2026-05-05

## Summary

Added a per-plant-group bulk harvest path to the bed view. The status pill in the right-side "Plants in [Bed Name]" panel now morphs to a clickable green **"Harvest! (N)"** button when at least one item in the group is past its expected harvest date and not already harvested. Clicking the pill opens a small modal that takes one weight number for the whole batch (matching the user's "we measure by bed" mental model). Submission posts to a new `POST /api/harvests/bulk` endpoint that creates N HarvestRecords sharing a single `harvest_group_id` UUID, and runs the same per-item auto-sync (PlantedItem → harvested, PlantingEvent → completed, IndoorSeedStart → transplanted) that the single-cell endpoint already used.

Per-cell harvest from the plant detail panel (shipped previously) is unchanged — the pill is the bulk shortcut, the panel is the precision tool.

## Design decisions (confirmed with user)

- **Readiness rule (#1)**: at least one item in the group has `calculateHarvestDate(item, plant) <= now` AND `status !== 'harvested'` AND `!saveForSeed`.
- **Record shape (option B)**: N HarvestRecords sharing a `harvest_group_id` UUID — same convention as `succession_group_id`. Single-cell harvests leave the column null.
- **Quantity model**: one total weight at the bed, evenly split per record (`totalQuantity / N`). Frontend can re-aggregate by `harvestGroupId`.

## Out of scope (backlog)

- **Mixed-readiness groups**: today, when only some items in a group are past harvest, the pill renders `Harvest! (N)` where N is the ready count. Items past harvest are bulked; not-yet-ready items keep growing in the bed. This is correct behavior, but UX could surface that more clearly (e.g., "Harvest 3 of 5 ready").
- **Harvest window option (#2)**: the readiness rule fires the day DTM elapses and stays fired indefinitely. If long-window crops (peppers, tomatoes) generate noisy pills, consider adding a 30-day decay window per the original design discussion.
- **Editing or undoing a bulk harvest**: today, deleting one of the N records leaves the others orphaned in the group. Could add a "delete by harvest_group_id" endpoint if users find this confusing.
